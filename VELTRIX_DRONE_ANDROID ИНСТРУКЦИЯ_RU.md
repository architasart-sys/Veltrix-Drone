# 1. Что такое Veltrix Drone Android

Veltrix Drone Android — мобильная инженерная система для работы с парком БПЛА непосредственно с телефона или планшета.

Приложение хранит собственные локальные данные и позволяет работать независимо от Windows.

Основной принцип:

```text
Android
   ↓
локальная база
   ↓
работа без компьютера
   ↓
при необходимости
   ↓
обмен с Windows
```

Это не пульт дистанционного управления Windows-программой.

---

# 2. Главное отличие от Windows

Windows и Android являются отдельными приложениями.

## Android может самостоятельно

- создавать и изменять дроны;
- вести аккумуляторы;
- работать со складом;
- вести KIT;
- создавать ремонты;
- создавать осмотры;
- вести ТО;
- планировать вылеты;
- создавать полёты;
- вести Preflight/Postflight;
- хранить вложения;
- выполнять локальные инженерные расчёты;
- создавать резервные копии;
- восстанавливать локальные данные.

Windows нужен только если вы хотите обмениваться общими данными между компьютером и Android.

---

# 3. Установка APK

## Шаг 1. Скачайте APK

Скачивайте APK только из официального GitHub Release проекта Veltrix Drone.

Файл обычно имеет формат:

```text
Veltrix_Drone_Android_....apk
```

## Шаг 2. Откройте APK

На телефоне откройте загруженный файл.

Если Android запрещает установку, система предложит разрешить установку приложений из этого источника.

Название системного пункта зависит от производителя телефона.

## Шаг 3. Разрешите установку

Разрешите установку только для того приложения, через которое вы открываете официальный APK.

## Шаг 4. Установите Veltrix Drone

Нажмите:

```text
Установить
```

После завершения:

```text
Открыть
```

> [!WARNING]
> Не скачивайте APK из случайных Telegram-каналов, файловых обменников и сторонних сайтов.

---

# 4. Первый запуск

Новая установка Android запускается сразу как самостоятельное приложение.

Подключение к Windows при первом запуске не требуется.

То есть правильный сценарий:

```text
Установили APK
→ Открыли Veltrix Drone
→ Начали локальную работу
```

Подключить Windows можно позже.

---

# 5. Автономный режим

Автономный режим является нормальным рабочим режимом Android.

В нём:

- компьютер не нужен;
- Windows-сервер не нужен;
- локальная сеть не нужна;
- интернет не нужен для основной работы;
- локальная база остаётся на телефоне;
- backup/restore работают локально.

Если в разделе синхронизации Windows отключён — приложение продолжает работать.

---

# 6. Навигация

Veltrix Drone Android адаптирован под мобильный экран.

Основные функции доступны через главный интерфейс и навигацию приложения.

Расширенные системные функции находятся в разделе:

```text
Ещё
```

В частности, подключение к Windows находится здесь:

```text
Ещё
→ Обмен и синхронизация
```

На небольшом экране списки и карточки прокручиваются вертикально.

# 7. Как начать работу с нуля

Для полностью автономной Android-базы рекомендуется такой порядок:

```text
1. Добавить дроны
2. Добавить аккумуляторы
3. Заполнить склад
4. Создать KIT при необходимости
5. Заполнить компоненты
6. Привязать компоненты к узлам
7. Добавить ТО
8. Создать план вылета
9. Выполнить Preflight
10. Записать полёт
11. Выполнить Postflight
12. Создать первую резервную копию
```

Windows можно подключить как до, так и после этого.

# 8. Дроны

Откройте раздел дронов.

## Добавление

Нажмите кнопку создания нового аппарата.

Используйте уникальный код, например:

```text
DRN-001
DRN-002
DRN-003
```

Заполните доступные сведения:

- модель;
- серийный номер;
- состояние;
- налёт;
- место;
- заметки;
- экономические поля;
- другие доступные параметры.

## Редактирование

1. Откройте дрон.
2. Выберите редактирование.
3. Измените данные.
4. Сохраните.

## Удаление

Удаляйте запись только если уверены, что аппарат действительно нужно удалить из локального учёта.

Если Android подключён к Windows, после следующего обмена изменения общих сущностей могут быть переданы между устройствами в пределах поддерживаемого Bridge.

---

# 9. Карточка дрона

Карточка дрона объединяет мобильные данные по аппарату.

Используйте её как точку входа в:

- основную информацию;
- техническое состояние;
- компоненты;
- полёты;
- обслуживание;
- ремонты;
- инженерные данные;
- вложения;
- историю.

На Android большие блоки организованы под вертикальную прокрутку.

---

# 10. Аккумуляторы

Откройте раздел аккумуляторов.

Для каждого физического аккумулятора рекомендуется отдельная запись.

Пример кодов:

```text
BAT-001
BAT-002
BAT-003
```

Учитывайте:

- модель;
- серийный номер;
- циклы;
- состояние;
- параметры LiPo;
- стоимость;
- заметки;
- связь с аппаратами.

## Практика

Не создавайте одну запись «Батареи» для нескольких физических аккумуляторов.

Иначе теряется индивидуальная история.

---

# 11. Склад

Склад Android работает локально.

Используйте уникальные SKU:

```text
STK-0001
STK-0002
```

Основные операции:

- создание позиции;
- изменение остатка;
- приход;
- выдача;
- возврат;
- списание;
- экономический учёт.

При выдаче детали на аппарат связывайте движение с соответствующим дроном, если экран это позволяет.

---

# 12. Комплекты KIT

KIT объединяет несколько складских позиций.

Пример:

```text
KIT-001
```

Используйте комплекты для:

- набора запасных частей;
- комплекта обслуживания;
- выездного набора;
- комплекта под конкретную задачу.

При синхронизации с Windows общие KIT могут обновляться, но локальные KIT не должны удаляться только потому, что их нет на компьютере.

---

# 13. Компоненты и привязка к узлам

Android поддерживает учёт физического компонента и его позиционной привязки.

Логика:

```text
компонент
→ дрон
→ узел / позиция
```

Пример:

```text
MOTOR-014
→ DRN-002
→ передний правый мотор
```

## Установка компонента

1. Найдите компонент.
2. Выберите аппарат.
3. Выберите технический узел.
4. Зафиксируйте установку.
5. Добавьте дату / исполнителя / заметку, если поля доступны.

## Снятие компонента

При фактическом снятии фиксируйте снятие, а не просто меняйте текст заметки.

Это важно для истории ресурса.

---

# 14. Ремонты

Ремонт создаётся для конкретного технического события.

Заполняйте:

- аппарат;
- проблему;
- узел;
- описание;
- статус;
- стоимость;
- выполненные действия;
- примечания.

Хорошее описание:

```text
После посадки обнаружена трещина переднего правого луча.
На проверке двигателя FR появилась повышенная вибрация.
```

Плохое:

```text
сломался
```

История ремонтов участвует в дальнейшем инженерном анализе.

---

# 15. Осмотры и чек-листы

Осмотры позволяют фиксировать состояние аппарата в конкретный момент.

Используйте их:

- перед техническими работами;
- после ремонта;
- после хранения;
- при периодической проверке;
- при обнаружении подозрительного состояния.

Если осмотр синхронизируемого типа, он может участвовать в обмене с Windows.

---

# 16. Плановое ТО

Создавайте задачи обслуживания на Android независимо от Windows.

Указывайте:

- дрон;
- название работы;
- срок;
- статус;
- заметки;
- другие доступные параметры.

Не закрывайте ТО до фактического выполнения работ.

---

# 17. Планирование вылетов

Создайте план вылета до фактического полёта.

Связывайте:

- дрон;
- дату;
- задачу;
- аккумулятор;
- другие доступные данные.

План вылета входит в список общих сущностей, поддерживаемых обменом с Windows.

---

# 18. Предполётные проверки

Перед полётом выполните Preflight.

Рабочая последовательность:

```text
План
→ Preflight
→ Полёт
```

Фиксируйте замечания до начала полёта.

Если проверка не пройдена — техническую проблему лучше устранить и записать, а не игнорировать.

---

# 19. Полёты

После вылета создайте или завершите запись полёта.

Записывайте фактические данные:

- аппарат;
- дату;
- длительность;
- LiPo;
- результат;
- замечания;
- технические события.

Полёты являются одной из общих сущностей Windows ↔ Android.

---

# 20. Послеполётные проверки

После полёта выполните Postflight.

Фиксируйте:

- повреждения;
- вибрацию;
- нестандартное поведение;
- проблемы связи;
- состояние питания;
- необходимость ремонта;
- необходимость диагностики.

Рабочая цепочка:

```text
Полёт
→ Postflight
→ при необходимости ремонт / диагностика
```

---

# 21. Вложения

Android хранит локальные вложения независимо от Windows.

Можно использовать:

- фотографии;
- документы;
- другие поддерживаемые файлы.

Пример:

```text
Фото трещины
→ ремонт
→ DRN-002
```

## При синхронизации

Метаданные удалённых вложений и локальные физические файлы обрабатываются отдельно.

Поэтому отсутствие локального файла Windows не должно автоматически означать удаление Android-файла.

---

# 22. Инженерные функции

Android содержит локальные инженерные модули.

Они не требуют Windows для расчётов.

В зависимости от текущей сборки доступны контуры:

- техническое здоровье;
- прогноз ТО;
- инженерный центр;
- конфигурация;
- деградация;
- технические циклы;
- надёжность;
- системные случаи;
- другие перенесённые инженерные экраны.

> [!IMPORTANT]
> Инженерные статусы — это объяснимые результаты по фактическим данным, а не случайная вероятность отказа.

---

# 23. Тренды и деградация

Android может анализировать динамику нескольких технических показателей.

В текущей мобильной архитектуре учитываются, среди прочего:

- индекс состояния;
- просадка LiPo;
- LQ;
- температура;
- максимальный ток;
- mAh/мин;
- группировка сигналов по узлам;
- остаточный ресурс деталей;
- динамика зарегистрированных отказов.

Используйте тренд не по одному полёту, а по накопленной истории.

---

# 24. Контроль конфигурации

Android поддерживает Configuration Drift Workflow.

Типовая последовательность состояния отклонения:

```text
Открыто
→ Проверено
→ Подтверждено
→ Принято
или
→ Устранено
```

Принятое отклонение может оставаться предупреждением.

Устранённым отклонение должно считаться только при фактическом соответствии baseline.

Новый baseline может закрывать активные отклонения, относящиеся к предыдущему эталону.

---

# 25. Технический цикл

Android хранит данные технического закрытия и контрольные снимки.

Используйте технический цикл для последовательности:

```text
Проблема
→ технические работы
→ проверка
→ готовность
→ закрытие
```

Если экран показывает блокеры — сначала устраните фактические причины, затем повторяйте проверку.

---

# 26. Надёжность

Мобильная версия позволяет работать с локальными инженерными данными надёжности.

Не делайте выводы по пустой базе.

Для полезного анализа нужны:

- полёты;
- налёт;
- зарегистрированные отказы;
- ремонты;
- история компонентов;
- повторяемые события.

---

# 27. Экономические данные

Android хранит локальные экономические поля.

При синхронизации общих сущностей локальные экономические значения не должны без необходимости затираться данными Windows.

Записывайте фактические:

- стоимости;
- расходы;
- стоимость деталей;
- стоимость ремонта;
- другие доступные экономические данные.

---

# 28. Резервные копии

Локальные ZIP-резервные копии Android работают самостоятельно и не требуют Windows.

Создавайте backup:

- после первоначального заполнения;
- перед обновлением APK;
- перед крупными изменениями;
- перед восстановлением;
- регулярно во время эксплуатации.

## Хорошая практика

Храните хотя бы одну свежую копию вне телефона:

- на компьютере;
- на внешнем накопителе;
- в выбранном вами защищённом хранилище.

---

# 29. Восстановление

Восстановление локальной резервной копии не требует Windows.

Перед восстановлением:

1. Создайте текущий backup.
2. Убедитесь, что выбран правильный ZIP.
3. Не прерывайте процесс.
4. После восстановления проверьте дроны, аккумуляторы и последние записи.

> [!WARNING]
> Не используйте Android **«Очистить данные»** как способ восстановления или обновления.

---

# 30. Подключение к Windows

Подключение выполняется только по желанию.

На Android откройте:

```text
Ещё
→ Обмен и синхронизация
```

На Windows откройте:

```text
Система
→ Мобильная связь
```

Компьютер и телефон должны находиться в одной локальной сети.

---

# 31. Первая синхронизация

## На Windows

1. Откройте **Мобильная связь**.
2. Запустите локальный сервер.
3. Найдите адрес.
4. Найдите порт.
5. Скопируйте токен.

## На Android

1. Откройте **Ещё → Обмен и синхронизация**.
2. Включите подключение Windows.
3. Введите адрес Windows.
4. Введите порт, если он вводится отдельно.
5. Введите токен.
6. Сохраните параметры.
7. Запустите синхронизацию.

После успешного соединения выполните обмен.

# 33. Как работает merge

Windows не считается «главной базой», которая полностью заменяет Android.

При получении данных:

```text
существует на обеих сторонах
→ запись обновляется / объединяется

есть только на Android
→ запись сохраняется

есть только на Windows
→ общая поддерживаемая запись добавляется на Android
```

То есть подключение Windows — **обмен между двумя сторонами**, а не уничтожение локальной базы Android.

## Важный результат

Локальные:

- дроны;
- KIT;
- ТО;
- полётные записи;
- экономические значения;

не должны исчезать только потому, что их нет на Windows.

---

# 34. Что остаётся только на Android

Не все новые инженерные сущности Android поддерживаются текущим Windows Mobile Bridge.

Поэтому часть новых инженерных модулей:

- полностью работает локально;
- хранит данные на Android;
- не зависит от Windows;
- может пока не передаваться на компьютер.

Это не ошибка автономной работы приложения.

---

# 35. Отключение Windows

Вы можете отключить Windows-подключение в любое время:

```text
Ещё
→ Обмен и синхронизация
```

После отключения:

- приложение продолжает работать;
- локальная база остаётся;
- локальные записи остаются;
- backup остаётся доступен;
- инженерные функции продолжают работать.

Удаление параметров Windows не должно удалять локальную Android-базу.

# 36. Обновление APK

Правильный способ обновления:

1. Создайте локальную резервную копию.
2. Скачайте новый официальный APK.
3. Откройте APK.
4. Установите обновление поверх существующей версии.
5. Не удаляйте старое приложение перед обновлением.
6. Не выполняйте **«Очистить данные»**.
7. После запуска проверьте несколько ключевых записей.

Если Android спрашивает:

```text
Обновить это приложение?
```

подтвердите обновление.

# 37. Смена языка

Android-интерфейс содержит русские и английские строки.

Используйте настройку языка приложения, доступную в интерфейсе текущей сборки.

После смены языка основные элементы интерфейса переключаются между:

```text
Русский
English
```

Если часть ранее введённых пользовательских данных остаётся на исходном языке — это нормально: пользовательские записи автоматически не переводятся.

# 38. Работа без интернета

Для обычной локальной работы интернет не нужен.

Без интернета можно:

- открывать приложение;
- создавать записи;
- редактировать данные;
- работать с инженерными модулями;
- использовать локальные вложения;
- создавать backup;
- восстанавливать backup.

Для обмена Windows ↔ Android нужен не интернет, а общая локальная сеть.

# 40. Что делать при проблемах

## APK не устанавливается

Проверьте:

- достаточно ли свободного места;
- разрешена ли установка из выбранного источника;
- не повреждён ли APK;
- скачан ли файл полностью.

---

## После обновления приложение пустое

Не выполняйте очистку данных.

Если данные действительно отсутствуют:

1. не создавайте много новых записей;
2. откройте резервные копии;
3. восстановите последнюю подтверждённую ZIP-копию.

---

## Windows не подключается

Проверьте по порядку:

1. телефон и ПК в одной сети;
2. Windows Mobile Connection запущен;
3. указан правильный локальный IP;
4. указан правильный порт;
5. указан актуальный токен;
6. Windows Firewall разрешает соединение для частной сети.

---

## Синхронизация прошла, но новый инженерный модуль не появился на Windows

Это может быть нормальным ограничением текущего Mobile Bridge.

Некоторые новые Android-инженерные сущности пока являются локальными.

---

## После синхронизации запись есть только на телефоне

Если сущность не входит в поддерживаемый список обмена, она останется локальной.

Если входит — повторите синхронизацию и проверьте параметры подключения.

---

## Не прокручивается экран

Убедитесь, что жест начинается внутри прокручиваемой области.

На больших формах используйте вертикальный свайп.

---

# 41. FAQ

## Android работает без Windows?

Да. Это основной архитектурный принцип мобильной версии.

## Нужно выбирать «Только телефон» при первом запуске?

Нет. Новая установка автоматически работает автономно.

## Если отключить Windows, данные удалятся?

Нет. Отключение соединения не должно удалять локальные данные.

## Windows заменяет Android-базу при синхронизации?

Нет. Используется merge/upsert общих сущностей.

## Нужен интернет для синхронизации?

Нет. Нужна общая локальная сеть между ПК и телефоном.

## Можно создать дрон только на Android?

Да.

## Можно создать ремонт только на Android?

Да.

## Можно сделать backup без Windows?

Да.

## Можно восстановить backup без Windows?

Да.

## Все инженерные данные передаются Windows?

Нет. Mobile Bridge пока поддерживает не все новые Android-инженерные сущности.

## Нужно удалять приложение перед обновлением?

Нет. Устанавливайте новую версию поверх существующей.

## Можно нажать «Очистить данные» перед обновлением?

Нет, если нужно сохранить локальную базу.

# 42. Безопасность

Рекомендуется:

- скачивать APK только из официального Release;
- не публиковать токен Windows;
- не открывать Windows Mobile Bridge в публичный интернет;
- регулярно создавать backup;
- не хранить единственную резервную копию только на телефоне;
- не выполнять Clear Data без необходимости;
- проверять данные после обновления;
- использовать частную локальную сеть для синхронизации.
